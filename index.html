your email validation sucks

If your signup form rejects addresses like alex@startup.dev or sam@community.engineer, your validator is probably stuck in the past.

Short version: modern email validation should accept real domains with newer TLDs, reject obviously malformed input, and avoid trying to fully re-implement the email RFCs in one giant regex.

New TLDs are real

Newer top-level domains like .app, .dev, .email, .studio, .technology, and .engineer are valid and widely used. A validator that only allows a short hard-coded list of legacy TLDs will reject legitimate users.

  • hello@product.app
  • team@company.email
  • jobs@future.engineer
  • support@design.studio

What good validation looks like

  • Require one @ with non-empty local and domain parts.
  • Allow long alphabetic TLDs instead of assuming .com length rules.
  • Reject whitespace and clearly malformed domains like double dots.
  • Prefer confirmation emails over increasingly fragile regex complexity.

Practical regex examples

These examples intentionally aim for pragmatic validation rather than full RFC completeness: they accept common real-world addresses, including newer TLDs, while blocking obvious mistakes.

JavaScript

const emailPattern =
/^[A-Za-z0-9!#$%&'*+/=?^_`{|}~-]+(?:\.[A-Za-z0-9!#$%&'*+/=?^_`{|}~-]+)*@(?:[A-Za-z0-9](?:[A-Za-z0-9-]{0,61}[A-Za-z0-9])?\.)+[A-Za-z]{2,63}$/;

Python

EMAIL_RE = re.compile(
    r"^[A-Za-z0-9!#$%&'*+/=?^_`{|}~-]+(?:\.[A-Za-z0-9!#$%&'*+/=?^_`{|}~-]+)*@"
    r"(?:[A-Za-z0-9](?:[A-Za-z0-9-]{0,61}[A-Za-z0-9])?\.)+[A-Za-z]{2,63}$"
)

Ruby

EMAIL_RE = /\A[A-Za-z0-9!#$%&'*+\/=?^_`{|}~-]+(?:\.[A-Za-z0-9!#$%&'*+\/=?^_`{|}~-]+)*@(?:[A-Za-z0-9](?:[A-Za-z0-9-]{0,61}[A-Za-z0-9])?\.)+[A-Za-z]{2,63}\z/

Go

var emailPattern = regexp.MustCompile(
    "^[A-Za-z0-9!#$%&'*+/=?^_`{|}~-]+(?:\\.[A-Za-z0-9!#$%&'*+/=?^_`{|}~-]+)*@" +
        "(?:[A-Za-z0-9](?:[A-Za-z0-9-]{0,61}[A-Za-z0-9])?\\.)+[A-Za-z]{2,63}$",
)

One more thing

Regex is a first pass, not proof that an address can receive mail. After basic format checks, the most reliable validation is still: let the user submit, then send a verification email.
